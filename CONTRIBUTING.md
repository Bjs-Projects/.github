# Contributing

Before repository work, read the live `Bjs-Projects/docs/WORKFLOW.md` from `main`. It defines the Bjs-specific repository workflow; the target repository defines its requirements, commands, and acceptance criteria.

- Identify the exact repository and relevant issue.
- Work on a descriptive branch rather than directly on `main`.
- Run the repository's local validation before opening a pull request.
- Complete the inherited pull-request template with the result, refs, verification, delivery, and real limitations.
- Resolve review discussions before integration.
